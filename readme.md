🧪 Postman API Testing - Chaining Project
This project demonstrates API Request Chaining using Postman, where each request is dependent on the response of the previous one. It utilizes environment variables to handle dynamic data and ensures smooth data flow between the requests.

📌 Collection Includes:
✅ POST Create user

📥 GET Retrieve user details

✏️ PUT Update user details

❌ DELETE Remove user

🧠 Concepts Used:
Environment Variables: Used for storing dynamic values (e.g., user ID, email, name) to ensure the reusability of the requests.

Pre-request Script: Dynamically generates random data (e.g., random email and name) for each API request.

Test Script Assertions: Verifies the API responses (e.g., matching the user ID, email, and name from the POST request).

JSON Parsing: Extracting and manipulating data from the JSON response.

Response Chaining: Using values from the response of one request (e.g., user ID) in subsequent requests.

🚀 How to Run:
Import the Collection:
Import the collection file GoRestapicollection.postman_collection.json into Postman.

In Postman, go to File > Import > Choose Files and select the collection JSON file.

Set the Bearer Token:

Add your Bearer Token to the environment or set it in the Authorization tab of Postman. You can do this by going to the Environment settings and adding the token under variables or directly within the request.

Run the Requests:

Step-by-step: You can run each request individually to observe how each one builds on the data from the previous request.

Collection Runner: Alternatively, use the Collection Runner to run all the requests in sequence, which will automatically utilize the environment variables for chaining.

📋 Example of Data Flow:
POST Create User: Creates a user with a dynamically generated name and email, storing these values in environment variables (name_env, email_env).

GET Retrieve User: Retrieves the user details using the userid_env variable, validating that the details match the values from the POST request.

PUT Update User: Updates the user with a new name and email generated by the pre-request script.

DELETE Remove User: Deletes the user using the userid_env variable and clears all environment variables used in the process.

🔑 Authentication:
This collection uses Bearer Token Authentication for API access. Ensure you provide the token in the authorization settings for each request.
